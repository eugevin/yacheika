# Yacheika

A cooperative browser game. The group walks the same cell of the Gigakhrushch (Samosbor style) again and again: a stair landing, the shared floor corridor, a Soviet three-room flat, a loggia. Spot an anomaly — turn back; don't — go forward. You need 10 correct passes in a row; a mistake resets the count. Some anomalies are seen by only one player, who has to convince the others.
TypeScript without frameworks: a Vite + Three.js client and an authoritative Node server on `ws`. Sound is synthesized with Web Audio, voice chat runs over WebRTC (mesh) with positional audio. No assets: all textures are drawn on canvas.

Game design (rules, cell, style, light, sound, anomaly catalogue, samosbor) is in `docs/DESIGN.md`, deployment in `docs/DEPLOY.md`, planned work in `docs/ROADMAP.md`. All interface text is in Russian; code comments, documentation and commit messages are in English.

## Commands

```
npm run server   # game server on :8788 (node --watch); serves the built client too if dist/ exists
npm run dev      # Vite client; /ws is proxied to YACHEIKA_SERVER (default ws://localhost:8788)
npm run dev:lan  # the same, but on the whole network and over HTTPS (self-signed cert), otherwise no microphone on a LAN address
npm run build    # tsc --noEmit + vite build; this is the type check
docker compose up -d --build   # production on a VPS: app + Caddy (HTTPS for DOMAIN) + coturn; settings in .env, see docs/DEPLOY.md
```

The production image (`Dockerfile`) is Node 24 LTS, local development is on Node 26: the server runs straight from `.ts`, so `server/` and `shared/` use only erasable syntax (`erasableSyntaxOnly`) and imports with the `.ts` extension.

There's no test framework. Server logic is checked with Node scripts: they import `Room` from `server/room.ts`, create players via `join(send, name)`, send `onMessage(p, { t: 'pos', c: cycleId, x, z, yaw, pitch })` and call `tick(now)` with a substituted time. The rate limiter uses the real clock, not `now`: a script that sends hundreds of `pos` within milliseconds will hit it (only the latest position matters, so usually this doesn't get in the way).

## Structure

- `shared/`: code shared by client and server.
  - `map.ts`: the cell as a list of rooms `ROOMS` (rectangle, height, floor and wall kind, windows) and doorways `DOORWAYS` between them. Rooms don't touch: there's a `WALL_T` = 0.12 m wall between them, and a doorway is a walkable rectangle across it (`doorRect`). The pantry is closed and impassable. Open doors stand at a right angle (`Doorway.leaf`, `leafRect`); their leaves and the furniture are walking obstacles (`BLOCKERS`). Also here: the Z-shaped passages beyond the exits (`EXIT_DOORS`, `VESTIBULES`), `tambourAt` (the whole passage past the blast door counts as taking the exit), `exitAt` (the `ZONE` for the seamless transfer), `loopPose`, `canStand` over `WALKABLE`, `inCell`, `roomAt`, spawn points; the stairs down behind the passage dead end after a win (`STAIRS`, `stairFloor`, `stairDepth`; `canStand(..., stairs)` lets you onto them only in the victory cell). Plus the passage skin thickness `GALLERY_SKIN` and the building wing `WING` around the front passage.
  - `furniture.ts`: where furniture stands (`FURNITURE`: box, height, room) — used to build the object, to compute walking obstacles and to occlude light.
  - `anomalies.ts`: the anomaly catalogue (`docs/DESIGN.md`, 6, by room): id, name, difficulty level 1–3.
  - `masks.ts`: what the player picks in the lobby — clothing (`OUTFITS`) and protective gear (`MASKS`); flat numbers `FLATS` (41–48), the server assigns the first free one.
  - `rules.ts`: balance constants: `GOAL`, anomaly chance, difficulty growth, private anomaly chance, `SAMOSBOR_MS` (10 s) and the samosbor timeline `SAMOSBOR`.
  - `protocol.ts`: messages between client and server.
- `server/`:
  - `index.ts`: HTTP (static files from `dist/`) and WebSocket on `/ws`, expects `join` as the first message. Messages are at most 64 KB (`MAX_PAYLOAD`), a ping every 15 s: whoever didn't answer the pong is disconnected, otherwise a vanished player would hold the exit until the end of the countdown. Limits: `MAX_CLIENTS` (300) sockets on the server, `MAX_PER_IP` (12) from one address, a socket that hasn't joined in `JOIN_TIMEOUT_MS` (10 s) is dropped. Behind Caddy every socket comes from the proxy, so with `TRUST_PROXY` (set by `docker-compose.yml`) the address is the last `X-Forwarded-For` entry; never set it when the server is reachable directly.
  - `rooms.ts`: rooms by code; a nonexistent code creates a room, up to `MAX_ROOMS` (100) at once.
  - `turn.ts`: STUN/TURN servers for voice, sent to the client in `hello`. With `TURN_HOST` and `TURN_SECRET` (set by `docker-compose.yml`) — our own coturn with temporary credentials valid for a day (the `use-auth-secret` scheme: username `expiry:tag`, password is its HMAC-SHA1); without them only public STUN, as in local development.
  - `room.ts`: one group: lobby, cycles, anomaly selection, exit countdown, verdict (one log line each: room, floor, anomaly id and whether it was private, the choice, right or wrong, how many of the group were out), samosbor, run statistics, WebRTC signal relay (`signal()` rebuilds them from known fields only). Rate limits (`Bucket`): 120 messages burst and 60 per second overall, chat and markers 8 burst and 2 per second; the excess is silently dropped.
- `src/`: the client.
  - `world/`: building the cell from scratch every cycle.
    - `index.ts`: `buildWorld(cycle, players)` and the `World` interface; `world.props` — everything anomalies touch, by room; the «ЭТАЖ N» stencil and the «Памятка жильцу» memo; baking and mesh merging.
    - `shell.ts`: walls with cut-outs for doorways and windows, floors, ceilings, skirting boards, reveals, door frames, windows; all from the description in `map.ts`.
    - `tambour.ts`: tambours (the passages beyond the exits): green paint up to 1.5 m, whitewash, metlakh tile, cable duct, caged lamp; outside, the concrete skin of the inter-block passage. The dead end (`deadEnds`) is separate instances, hidden in the victory cell.
    - `stairs.ts`: the exit after a win (`docs/DESIGN.md`, 7.3): behind each tambour's dead end a landing, 16 steps down one floor, a lower landing with a lamp, a door and an «ВЫХОД» (exit) sign. Built only by `buildWorld(..., won)`, baked separately every time (`stairSpace`: tambour plus stairs, its own lamp and the tambour lamp), outside the cache; the tambour itself is baked as always, so the stairs appearing isn't noticeable from the zone.
    - `smog.ts`: samosbor fog in shaders: a uniform part plus a floor layer, density falls exponentially with height, the ray integral in closed form. Shared uniforms `SMOG`, wired into `useBaked()`, lamp glass (`smogged`), `outdoorMaterial` and the yard sky. At zero density the shader skips it entirely — a normal cell renders bit-for-bit as without it.
    - `surfaces.ts`: procedural surfaces per `docs/DESIGN.md`, 3.1 — colour, relief and roughness; `pictures.ts`: rugs, portrait, calendar, notices, signs.
    - `furniture.ts`: `Kit` — assembling objects from primitives in a box from `shared/furniture.ts`, room materials; `keep()` marks what anomalies touch.
    - `rooms/*.ts`: furnishing of the rooms (landing and corridor, hallway, kitchen, bathroom with toilet, living room, bedroom with loggia); each returns its objects for `world.props`.
    - `exterior.ts`: our building's facade with windows of other floors, black floor slabs; the front passage together with the victory stairs is hidden in a blank building wing (`WING` in `shared/map.ts`), otherwise a Z-shaped tube hanging in the air, seen from the bedroom and loggia windows, would give the loop away; `yard.ts`: the night yard — rows of panel blocks in black murk with lit windows, driveways with sodium street lamps, lamps with canopies over the entrances, bare trees (crossed cards), snow and wet asphalt; the murk is brown from the street lamps below and black above. Its own material `outdoorMaterial({...})` without baking: street light is one ground map `streetLight()` (half-float texels per metre: red — street lamps, green — entrances, blue — driveways), walls take light at their base and it fades with height, never reaching our floor; lit windows are `glowMap`/`glow` (`glowMaterial`), they shine through the murk farther than anything else. "All windows dark" zeroes `glow`.
    - `lighting.ts`: baked light (`docs/DESIGN.md`, 4.1): direct lamp light occluded by walls, window light, bounce light, ambient occlusion; lamp channels `CHANNELS`; `useBaked()` injects it into a material; `kelvin()` — colour by temperature with a 3500 K white balance.
    - `lamps.ts`: a lamp = a baked light channel (`LampSpec`: position, style, temperature, intensity in candela); `env.ts`: per-room environment maps, captured once.
    - The lamp table by room (`LAMPS`) and finishes (`FLOORS`, `WALLS`, `CEILINGS`) are in `world/index.ts`.
    - `wear.ts`: wear (`docs/DESIGN.md`, 4.6) — decals from one atlas in one material (one draw call): dirt around switches, wallpaper peeling at the ceiling, rust streaks on ceilings, worn linoleum at thresholds, limescale in the bathroom, soot above the stove, chipped paint and mop streaks low on the landing and corridor walls; plus the switches by the doors themselves. Only in rooms, nothing in the tambours.
    - `geometry.ts`: `plane` (UVs in metres, split into tiles), `flat`, `quad`, `box`, `mount`.
    - `layers.ts`: render layers. After merging the whole cell goes to the `far` layer, which is enabled on the main camera, the raycaster and the environment map cameras; whatever is added later (players, anomalies) stays on layer 0. Each real mirror (`mirror.ts`, `realMirror`: the hallway one in `rooms/hall.ts`, the washbasin one in `rooms/bath.ts`, the dresser one in `rooms/bedroom.ts`) renders layer 0 and its own view layer, where the cell meshes near it are as well (`MIRROR_VIEWS` in `world/index.ts`); the hallway one also renders the `mirror` layer (what's visible only in the mirror, like "Extra in the mirror"). A mirror renders only while the camera is in one of the rooms it's seen from; mirrors themselves are on `far` only, so one is never drawn inside another's reflection. On low quality there are no reflections (`world.setQuality`).
  - `post.ts`: post-processing on high quality (`docs/DESIGN.md`, 4.5): the scene in HDR half float with MSAA, bloom (`UnrealBloomPass`, threshold 1.8 — above any lit wall: lamps and lit windows), then a single pass — the same ACES as the renderer without post-processing, sRGB, "Soviet film" (less colour, greenish shadows, warm faded highlights), vignette, slight chromatic aberration towards the corners, grain. Grain can be frozen (`post.frozen`, `yacheika.freeze()`). On low quality it renders straight to the screen. Samosbor fog is blended in HDR before tone mapping, so its colour is converted back through ACES (`setSmogColor`, `SMOG_SPACE.linear`).
  - `samosbor.ts`: samosbor on top of the cell where the mistake happened (`docs/DESIGN.md`, 7.1), timed from the verdict by `SAMOSBOR` in `shared/rules.ts`: red emergency light (`lamp.tint`/`set`, windows dim), the warning once at 0.8 s, from 2.5 s fog (visibility 40 → 2 m, the floor layer first), puffs from vent grilles (`VENTS` in `world/rooms/index.ts`), from under the neighbours' and pantry doors, from the garbage chute and from both ends of the tambours (one draw call, camera-facing planes, fading at the floor), from 6 s flicker and "swimming" screen edges (`#warp`), by 8.8 s the screen is covered (`#veil`), from 9.4 s silence; the next cycle at 10 s. Nothing is rolled back: the cell is rebuilt afterwards, `clearSmog()` turns the fog off. Time runs on the real clock, not the clamped `dt`, so a slow client doesn't fall behind the server.
  - `anomalies.ts`: the implementation of each anomaly by catalogue id. Helpers: `lit()` — a material lit by baked light at a point; `figure()` — a static character (double, extra in the mirror); `floorGlow()` — a glow on the floor. Anomaly sounds are `world.emitters` (`Emitter` in `world/index.ts`: continuous ones like the burner hiss, and events with `every`/`at` or one-shots with `near`), each with its own `range`.
  - `textures.ts`: procedural textures and the deterministic `rng(seed)`.
  - `player.ts`: first-person walking, keys by `e.code` so the Russian layout works; footsteps and head bob.
  - `character.ts`: a resident (`docs/DESIGN.md`, 3.3) — clothing in the player's colour, a «ДНД» (volunteer patrol) armband on the left shoulder, an ID card with surname and flat number. It's **one `SkinnedMesh`, one draw call**: the pieces (`Parts`) are each bound whole to one bone (`BONE`: body, chest, head, shoulders, hips, knees), colours are in vertex colours, pictures (face or gas mask front, ID card, armband, quilted jacket stitching, gauze) are in one 256×256 texture per character (`ATLAS`), the speaking glow is in its emissive map. The face is projected from the front (`FACE_FRAME`) onto a piece of sphere just above the skull. The gait is tied to the distance walked (one step per `STEP_LEN`, in time with the footstep sound), the head tilts by `pitch`.
  - `masks.ts`: head protective gear (GP-5, gauze, "Lepestok", welding mask, ushanka with scarf, none) and the L-1 hood; tells whether hair is visible.
  - `lobby.ts`: the "ID photo" in the lobby — its own small renderer with the player's character; it also draws the choice icons; closed on entering. The board's cork is `corkTexture()`.
  - `avatars.ts`: other players (`Character`) and markers; speech loudness comes from `Voice.levels()`.
  - `self.ts`: our own body (`SelfBody`), two `Character`s following the walker: one without a head (`hideHead()`, the head bone folded to a point) on the `far` layer, set `BACK` behind the camera so looking down shows the chest and legs, not the inside of the torso; and a whole one on the `self` layer, which only the mirrors draw. Left out of the environment maps like the avatars.
  - `voice.ts`: voice chat, mesh WebRTC; the newcomer always calls. ICE servers come from `hello` (`voice.ice`).
  - `audio.ts`: all sound except voice; the samosbor (`samosbor()`): a motor siren that winds up, wails between `SIREN_LOW` and `SIREN_HIGH` and runs down, its tone a `PeriodicWave` of eight harmonics (so nothing above 4 kHz), several detuned ports, wind gusts and an echo off the next blocks; the announcement twice; squelching, the call signs and announcement after a win (`allClear()`): the riser hum (the same everywhere), each lamp with its own voice (`LAMP_SOUND`: the tube in the kitchen hums, caged lamps crackle), sources from `world.ambience`, footsteps by surface, anomaly sounds; reverb by room type (`REVERB`), muffling behind walls (`MUFFLE`); positions the listener at the camera. Rhythmic sounds (clock, drops, meter, lift, fridge rattle) are a `Pattern` with a fixed period, scheduled slightly ahead by frame time; the clock ticks in time with the pendulum.
    - `world/ambience.ts`: where and what sounds in the cell — `ambience()` (fridge, wired radio with a waltz, dripping tap, clock, electricity meter, lift behind the landing wall; each with `range` and `on`), the surface underfoot (`footingAt`, rugs — `RUGS` in `shared/furniture.ts`), creaky parquet boards (`creaks`), room acoustics, `separation` (same room, adjacent through a doorway, behind a wall) and `reachesZone` for checking ranges.
  - `net.ts`: connection and reconnection.
  - `main.ts`: game loop, input, HUD, Esc menu with settings (mouse sensitivity, sound and voice volume, kept in `localStorage`), the «НЕИСПРАВНОСТЬ» (fault) screen when WebGL 2 won't start or the context is lost (the baked cell is gone with it, so it offers a reload).
- The markup and styles of the lobby (notice board), the Esc duty log, the end report and the HUD live in `index.html`. The font is a typewriter one from system fonts (`--type`), no assets.

## Invariants that must not be broken

- **The server trusts no field from the client.** Every message is unvalidated JSON: `index.ts` rejects anything that isn't an object with a string `t`, and `Room.onMessage` checks the type of every field before using it. An exception in a handler crashes the whole process with all rooms.

- **Private anomalies don't reach other clients.** `Room.cycleFor()` puts the anomaly into the `cycle` message only for whoever sees it. A new mechanic must not reveal whether there's an anomaly to those it isn't shown to; the verdict (`result`) reveals it only after the choice.
- **The cell is deterministic.** The base cell is always the same: players learn it by heart, that's the game. Randomness is allowed only inside an anomaly and only from the `rng(seed)` the server sends. Don't add random variation to `buildWorld`.
- **Every anomaly in `shared/anomalies.ts` must have an implementation in `src/anomalies.ts`.** On startup the client logs an error to the console if an implementation is missing. An anomaly changes only what `buildWorld` returned, or adds objects to `world.group`: the world is rebuilt every cycle, no need to roll changes back.
- **The seamless loop relies on the symmetry of the passages.** Beyond each exit is a Z-shaped passage, symmetric under a 180° rotation around the centre of its middle section (`MID_CENTER`). When a cycle is resolved, everyone standing in the `ZONE` is moved by `loopPose` into the back passage with that rotation, and the picture doesn't change (verified pixel by pixel). Therefore:
  - half a passage is built once as a template, and all four halves of both tambours are instances (`InstancedMesh`) with shared geometry and shared baked light (`buildTambours()` in `world/tambour.ts`). Add nothing asymmetric inside, including the shape of small details: a three-sided wire of the lamp cage looks different after a 180° rotation, so the face count is always even; and no fine texture detail on the tambour ceiling;
  - instance matrices are recomputed every frame relative to the camera in double precision (`follow`). Otherwise the GPU multiplies world matrices in single precision, and the two tambours (20 m apart) round differently — the loop shows thousands of differing pixels. Any shader for the tambour must account for `instanceMatrix` (like `outdoorMaterial`);
  - anything visible through sub-pixel gaps between planes must be black: the back of the facade and of the passage skin is black, above and below the building are black slabs. Otherwise the yard sky shows through the gaps, differently in the two halves;
  - from the `ZONE` neither the doorway nor the dead end may be visible; the zone bounds are derived from this condition;
  - from the zone almost the entire far wall of the first leg is visible, right up to the doorway, and the landing shines through the doorway. So the tambour is baked separately: only with its own lamp and in its own space (`vestibuleSpace`), where the doorway counts as a wall. The tambour has no environment maps;
  - one half (of the back tambour) is baked, and its light is shared by all four. The computation itself is still independent of 90° and 180° rotations anyway: the occlusion ray fan is symmetric under a quarter turn around the normal, the basis is tied to the vertical (`openness`);
  - post-processing depends only on the frame, except grain: freeze it before comparing (`yacheika.freeze()`);
  - the loop check is a pixel comparison of **screenshots** (`page.screenshot`) at a point in the "forward" zone and at the point `loopPose` moves it to. A copy of the WebGL canvas via `drawImage` without `preserveDrawingBuffer` is empty, and such a test always passes. Looking down, our own body (`self.ts`) is in the frame, and it breathes with time: two screenshots taken a moment apart differ on it even though the transfer itself (one frame) doesn't; keep it out of the frame, or compare its light instead (`world.probe` at both poses gives the same values).
- **Light is baked only.** The scene has no light sources: all lighting is vertex attributes (`bakeBase`, `bakeIdx`, `bakeW`) and `CHANNELS`, which the shader multiplies by the current lamp colours. Any new material must go through `useBaked()`, otherwise it'll be black; things that move (characters, anomaly objects) are lit from a single point: `useBaked(mat, probe)` and `world.probe(x, z, probe)`. To switch off, recolour or flicker a lamp — `lamp.set()`/`lamp.tint()`, no rebaking. The result of the first bake is cached by mesh order: `buildWorld` must always build them in the same order. The baking budget is 150 ms (currently about 140 ms headless, shown in F3). Furniture occludes light with its box from `shared/furniture.ts` but doesn't shadow itself (`Space.skip`); small objects are lit from a single point for the whole object. Environment maps are captured once and don't know about switched-off lamps; a cell with an anomaly is never captured (`world.anomaly`), we wait for the first clean one.
- **Brightness is tuned by measurement, not by eye.** Average frame brightness in each room 0.25–0.40, fewer than 1% overexposed pixels (measured on screenshots). When changing lamp intensities, materials, `EXPOSURE` or post-processing (`EXPOSURE_GAIN` in `post.ts` returns the light eaten by the vignette and colour grading), re-measure. Windows barely shine at night (`NIGHT_RADIANCE`), so the kitchen, bedroom and loggia lamps are stronger than in daytime.
- **No more than 300 draw calls** (F3). Meshes are merged by material within "units": the whole cell, each `keep()` object and each of its named parts. Matte materials are shared by all rooms (`Kit.custom`), glossy ones are per room for the sake of environment maps. Currently about 290 without other players (F3 shows scene draw calls, and in parentheses post-processing passes, about 14, which don't count toward the budget); a character is one draw call, so six with a "Double" fit; our own body is one more, and one per mirror that shows it. `renderer.info` is reset manually once per frame, because the mirror reflection is rendered within the frame.
- **No coplanar faces.** Intersecting parts (frame mullions and transoms, architraves) must not share planes, and overlays stand off the wall by at least 2–3 cm away from the camera: otherwise they flicker. Window frames are recessed into the reveals by a centimetre, other floors' windows stand 3 cm off the facade and are offset in depth (`polygonOffset`).
- **Wear doesn't look like an anomaly.** Don't put a noticeable one-off detail (stain, crack) where an anomaly can show something similar (the small bathroom mirror, the floor under the corridor lamps, the floor stencil), and nothing asymmetric in the tambours.
- **Large planes are split into 1 m tiles** (`plane()` in `world/geometry.ts`). A huge triangle whose vertex ends up beside the camera interpolates wrongly: a 42-metre wall turns black. Don't bring back whole planes.
- **A cycle starts in the back passage.** It is the "back" exit itself, so an exit counts only if the player has already been in any room of the cell this cycle (`Player.entered`, `inCell`).
- **Positions are tied to the cycle.** The client sends `pos` with `c = cycleId`; the server counts an exit only by positions of the current cycle, and clients ignore other players' positions from a different cycle.
- **The cell's sound is deterministic too.** A normal cell always sounds the same: riser, lamps, `world.ambience` sources, footsteps. Rhythms are fixed and counted from the start of the cycle (the clock from frame time, in time with the pendulum), lamp crackle is precomputed loops from `rng`. There are no random background sounds: any strange sound is an anomaly, and it's added only via `world.emitters` (knock, phone, creak) or flags like `world.follower`. An anomaly can switch a source off (`ambient.on = false`; for the clock also `props.living.clock.running`), change the radio (`reversed`, `announce`) or silence the whole cell (`world.silent`). Anomaly sounds at neighbours' doors are placed only at flats 43–48: from 41 and 42 they reach the "back" zone. The hum comes from each lamp separately and follows `lamp.level`, so light anomalies change the sound by themselves.
- **Sound must not break the loop.** Every cell source has a hard range (linear falloff to zero): `BUZZ_RANGE` (5 m) for lamps, `range` for `world.ambience` sources; none may reach the passage zone — the dev build logs an error to the console (`reachesZone`). Currently the closest are the landing lamp at 5.27 m from the "back" zone and the loggia lamp at 5.75 m from the "forward" zone; the lift is behind the south wall of the landing, farther from the zone. Reverb is fed after panning, so a distant source isn't audible in it either. In the tambours only the riser and their lamps sound; both tambour lamps use the same crackle loop (number 0) and get their voice immediately at the current volume, without a dip. Check: loudness in identical poses (via `loopPose`) in the "back" and "forward" zones matches, currently to within 0.3%.
- **Samosbor only after a mistake and only on top of the already shown cell.** A wrong verdict (and a tie between the exits; those who left decide by majority, stragglers in the cell don't count) moves the room into the `samosbor` phase: `cycleId` stays the same, the server's anomaly is cleared (the `cycle` message in this phase reveals nothing), exits don't count. After `SAMOSBOR_MS`, a new cycle from floor 0, always through a fade (with the same `cycleId` the client only changes `shownPhase`, so there's no seamless transfer). A correct pass is still instant.
- **Victory builds the cell around those standing in the zone.** The `won` phase comes with `run` (time since the first tick of the round and the number of samosbors). Whoever stands in the exit zone stays in place (`enterCycle(..., 'stay')`), the rest spawn in the back tambour through a fade; the dead ends of both tambours open onto the stairs. At the bottom of the stairs is the final screen (`#final`).
- **Server messages are handled on receipt**, not in `requestAnimationFrame`: a minimized tab has no frames, and WebRTC signals can't wait.

## How to add an anomaly

1. An entry in `ANOMALIES` (`shared/anomalies.ts`): id, name for the verdict screen, difficulty level.
2. A function with the same id in `APPLY` (`src/anomalies.ts`). If a new object is needed, add it to the room's furnishing (`src/world/rooms/`) and return it in its `Props`; wrap whatever the anomaly moves or hides in `keep()`, otherwise mesh merging fuses it with the rest of the furniture. The anomaly also gets the room roster (`People`: your own look and the others') — that's how "Double" copies a teammate, or in single player the player themselves.
3. Check in `npm run dev` via the browser console (dev build only):
   - `yacheika.anomalies()` — list of ids;
   - `yacheika.preview('figure')` — rebuild the corridor with this anomaly, `yacheika.preview()` — without an anomaly; the third argument is the seed, to know where the anomaly will appear: `yacheika.preview('double', 3, 12345)`;
   - `yacheika.lineup()` — all 24 combinations: for each outfit a row of six protective gear options across the floor corridor, rows one after another; `yacheika.lineup('robe')` — just one row;
   - `yacheika.teleport(x, z, yaw)` — move; `yaw = 0` looks towards −z, `Math.PI` towards +z, `-Math.PI / 2` along the floor corridor (+x). Landmarks: landing `(1.5, 1.5)`, corridor `x` 3.1–27.1 at `z` 0–3, hallway `(24.7, 4.6)`, living room `(24.75, 13.1)`, bedroom `(20.6, 12.6)`, loggia `(20.4, 15.9)`;
   - `yacheika.samosbor(4.2, true)` — start a samosbor in the shown cell and fast-forward to 4.2 s (`true` — stop there, for screenshots); `yacheika.preview()` removes it;
   - `yacheika.win()` — the victory cell around you (as if the group just passed the 10th floor), with stairs;
   - `yacheika.where()` — position, current cycle and fade. Zone centres: back `(-1.5, -4.32)`, forward `(14.06, 18.88)`;
   - `yacheika.lamp('kitchen', 0)` — brightness of a room's lamps (`null` — all); `yacheika.quality()` — toggle quality; `yacheika.freeze()` — freeze the film grain (`freeze(false)` — release), for pixel comparisons; `yacheika.world()` — the current `World`.
4. In game: **G** — graphics quality (high: environment maps, post-processing and render scale up to 1.5; low: without them), **F3** — frames per second, draw calls (budget 300), triangles, baking time.

## Environment and browser testing

- Ports 8788 (`npm run server`) and 5173 (`npm run dev`) belong to the developer's running instances: don't stop them. For checks, start a server on another port (`PORT=8795`) and Vite with `YACHEIKA_SERVER=ws://localhost:8795 npx vite --port 5199`, and stop them by PID.
- With `HTTP_PROXY`/`HTTPS_PROXY` set, localhost needs `curl --noproxy '*'`.
- Headless Chromium with WebGL: `--use-angle=swiftshader --enable-unsafe-swiftshader`. Convenient to drive via `puppeteer-core` with `executablePath: '/usr/bin/chromium'`, installed into a temporary folder.
  - Stub pointer lock before the page loads: `pointerLockElement` returns `document.body`, `requestPointerLock` is a no-op.
  - Run two players in **two separate browser instances**: two WebGL tabs in one headless browser crash the process.
  - Voice is checked with `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream`: `yacheika.voice().peers` should show `connected`.
  - Headless Firefox (`browser: 'firefox'`, `executablePath: '/usr/bin/firefox'`) renders the game the same as Chromium, but behind a proxy gathers no ICE candidates, so voice can only be checked in Chromium.
  - Sound is checked by measurement, not by ear: connect an `AnalyserNode` to `yacheika.sound().master` (the field is private only for TypeScript) and take RMS, peak and the spectrum above 4 kHz at different points via `yacheika.teleport`. Run with `--autoplay-policy=no-user-gesture-required`. Reference values: tambour and corridor ≈ 0.004 RMS, kitchen (tube, fridge, radio) ≈ 0.014, living room and bedroom ≈ 0.0025; with `world.silent` 0 (only footsteps and anomalies remain); footsteps — peaks around 0.04; samosbor: the siren alone ≈ 0.03 RMS with peaks up to 0.14, with the announcement and squelching 0.017–0.037 RMS with peaks of 0.09–0.18 (deliberately the loudest thing in the game), silence by 9.8 s; anomaly peaks around 0.1 (radiator knocking, drill, radio with a name — 0.07–0.14 a step or two from the source; crying and the cistern are deliberately quiet); above 4 kHz quieter than −95 dB (currently no louder than −98 even with footsteps, the backwards radio −100). Listen to an anomaly from a point where a player can stand, not from inside a wall next to the source; a one-shot sound (`near`) fires immediately on teleport, so start measuring before it. Catch short clicks (clock, drops) with continuous recording via `ScriptProcessorNode`, not by polling the analyser on a timer; headless renders 5–6 frames per second, so for sound measurements switch quality to low and hide the canvas.
- The microphone is only available in a secure context: `localhost` or HTTPS. Over `http://192.168…` the browser hides `navigator.mediaDevices` entirely; the lobby then unchecks the voice box and shows `#mic-warning`. For LAN there's `npm run dev:lan`, for the internet you need a tunnel or hosting with HTTPS.
